# 72. The one thing somebody wants the pad to do · ✅ Done · S

Asked for from the sofa, in the same breath as the pages: *bir app veya bir
kart eklenip bir script tetiklenebilir.* Two shapes were on the table - adding
a tile **from the pad**, which is a flow, a file format and a keyboard, and a
card pointed at a **folder**, which is a listing this surface has had since
item 40. The folder won, and the whole of it is eleven lines of config:
`System > Scripts` lists every executable file in `~/.config/omapad/scripts`,
labelled by its name without its extension, and A runs it.

Nothing else had to be built, which is the argument for it. A listed card is
read when its page settles, `%1` is quoted on the way in, `exec:` already runs
in a scope of its own so a daemon restart does not kill what it started, and
adding a capability is dropping a file in a folder rather than editing the
shipped tree. What it is not is a launcher: an app is an app, and the `Apps`
page is where those live.

**And it found a real fault in the rule under it.** *A listing that finds one
thing is drawn as a reading, and A does nothing on it* (item 40) is right
about a set of speakers and wrong about a folder: one script is not a fact
about the machine, it is a thing to run, and the card drew it big and refused
the press. The fix is the mark rather than the count - a listing marks the one
in force (`*` from `pactl`, `on` here), so a lone row **with** a mark is the
fact the card is furniture round, and a lone row without one is something to
run or to switch to. Devices keep the reading they had; a folder with one
script in it is a list of one.
