# 71. A card that could not name what it was closing · ✅ Done · S

Asked for from the sofa: *workspaces'deki windows'da windows yazacagina aktif
pencerenin adi yazsin, blurdan ne kapandigi belli olmuyor.* Right, and it is
the one place on this surface where a written line provably cannot do the job:
the menu blurs what is behind it, so the window `Close window` is about is a
shape you cannot read, and `WINDOWS` over four verbs says only what the page
is already called.

`detail` could never answer it - a sentence in a config file cannot know
anything live, which `writing.md` rule 8 has said all along. What could is
`meta`, which the bar has had since the nav cards learned to say what a place
is *doing*. So a **tile** takes one now, with the same `{from, ttl, empty}`
table and the same refresh, and what it says stands where the tile's written
line stands: the heading of a card of rows, the detail of anything else.

- **Only the page in front is asked.** A `meta` is a subprocess with a clock
  on it, and a command answering for a page nobody is looking at is the cost
  that refresh exists to avoid.
- **`empty` is what it says before the first answer**, not a blank: a heading
  that went away while a command was thinking would be the card saying nothing
  at all. `Windows` is its own `empty`, so the shipped card is never worse off
  than it was.
- **Through `drawable()`**, because a window titles itself and a title is
  exactly the string qml.md 8.6 is about.
- The heading is held off the **right** edge now and elides. It never needed
  to be: the only thing it could print was a label somebody had written to
  fit.
